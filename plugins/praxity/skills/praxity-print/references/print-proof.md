# Proof an office print

Use this guide before delivering a handout, worksheet or pocket aid on paper. Check the final PDF on the intended office printer and paper. Screen review alone leaves physical print untested. Commercial press work needs the printer's own production requirements.

## Set up the proof

Record the PDF output hash from its run receipt, proof date, page size and orientation. Record the printer, paper stock, color or grayscale, single-sided or duplex, and print scaling.

Start at actual size, 100%, on matching paper. Check the PDF page dimensions and the printer's printable area. Fit-to-page changes text, image and writing-area sizes; record and proof that setting if delivery requires it. For pocket output, preserve the intended dimensions when printing on a larger sheet and trimming. Check the finished size with a ruler.

Use the lighting and reading distance expected for the task. Choose text size for the audience and inspect the result; a default point size alone does not establish readability. [Sensory Trust clear-print guidance](https://www.sensorytrust.org.uk/resources/guidance/designing-with-clear-and-large-print) explains typeface differences and audience needs.

## Inspect and use the paper

- Check every page for clipped edges, missing text, poor page breaks and labels separated from their diagrams or response areas.
- Check the grayscale version as well as color. Labels, symbols or patterns must carry meaning when colors look alike. If photocopies will be distributed, inspect an actual photocopy for lost detail and faint lines.
- Keep backgrounds light enough for the task and avoid needless ink coverage. Check table rules, checkboxes and diagram lines for visibility on the delivered copy.
- For duplex output, check orientation and whether printing on the reverse interferes with reading or writing. Try the intended pen or pencil. Choose matte, writable stock when needed, then test it. Paper opacity affects show-through; see [BCcampus paper basics](https://opentextbc.ca/graphicdesign/chapter/6-5-paper-basics/).
- Fill in a realistic response by hand. Check room for the expected answer, line spacing and whether the page lies flat enough to use. An empty box looking large on screen is insufficient evidence.
- Scan each QR code from the actual delivered print or photocopy with an intended device. Verify its destination and keep a readable alternative address or resource ID. Record the device and result.

## Check images at their printed size

Calculate raster pixels per inch, PPI, from pixel dimensions divided by placed dimensions in inches. A 1200-pixel-wide image printed 6 inches wide has 200 PPI. Check both dimensions and inspect fine detail and diagram labels on paper. The current renderer fills the available width, so a small source image can be enlarged substantially.

300 PPI can be a useful target for detailed artwork viewed close up. It is not a universal pass/fail threshold; content, viewing distance and printer matter. Pure vector artwork has no raster PPI. Increasing a resolution label does not restore missing detail. [Adobe's print-resolution guidance](https://helpx.adobe.com/photoshop/desktop/crop-resize-transform/resize-adjust-resolution/resolution-specs-for-printing-images.html) describes how requirements vary with use.

These are manual review steps. The Print CLI does not provide a print checker or grayscale/dither conversion. Use an available viewer or printer setting for the proof and record what it did.

## Record the evidence

Keep proof findings in the document folder, tied to the output hash. For each check, record the result, conditions and remaining issues. Use explicit statuses such as passed, issues found, untested or not applicable with a reason. Keep visual PDF review, physical print, photocopy, QR scan, assistive-technology review and reader-task testing separate. A passed paper proof does not establish PDF accessibility or learner performance.

After changing source, settings or assets, regenerate and recheck affected findings against the new output. If the material can become stale or circulate separately, author a concise visible revision or date and contact where useful. The run receipt is not visible to a paper reader.
